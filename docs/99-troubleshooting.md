# 99. Troubleshooting

Each section below corresponds to one check in `scripts/lib/checks.sh`, run by
`scripts/doctor.sh`. When a check fails, `doctor.sh` prints the matching anchor from this
file so you can jump straight here.

<a id="node-version"></a>
## Node.js too old

`analytics-mcp`/`search-console-mcp` and this project's own scripts require **Node.js 22
or newer**. Check your version:

```
node -v
```

If it's older than 22, install a current LTS release from [nodejs.org](https://nodejs.org),
or with a version manager, e.g. nvm:

```
nvm install 22 && nvm use 22
```

<a id="gcloud-missing"></a>
## Google Cloud SDK missing or not on PATH

`gcloud` is required by `reconnect.sh` (and by `setup.sh`, which calls it) to produce
Application Default Credentials. If `command -v gcloud` finds nothing:

- Install it from [cloud.google.com/sdk/docs/install](https://cloud.google.com/sdk/docs/install).
- If you already installed it but it's still not found, make sure the SDK's `bin`
  directory was added to your shell's PATH — the installer usually offers to do this;
  re-run it if you skipped that step, or add the line to your shell profile manually and
  open a new terminal.

<a id="analytics-mcp-missing"></a>
## analytics-mcp not installed

`command -v analytics-mcp` found nothing. `analytics-mcp` (the GA4 MCP server) is a
Python package on PyPI, installed separately from `search-console-mcp` (which runs via
`npx`, no install step). Install it with [pipx](https://pipx.pypa.io/), which keeps it in
its own isolated environment:

```
pipx install analytics-mcp==0.7.0
```

Then re-run `./scripts/setup.sh`. See `02-mcp-servers.md` for the full picture on both
servers.

<a id="adc-missing"></a>
## No ADC file

There's no Application Default Credentials file at the location `.env`'s `ADC_FILE`
points to (or the default, `~/.config/gcloud/application_default_credentials.json`, if
`ADC_FILE` isn't set). This is expected the first time you set things up, or after the
credentials have been removed. Generate one:

```
./scripts/reconnect.sh
```

Then `/mcp` inside Claude Code to reconnect the servers.

If you're using a multi-account setup (`reconnect.sh --account <email>`), the ADC lives
under `.secrets/gcloud/<email>/`, not the default location — run
`./scripts/doctor.sh --account <email>` instead of plain `doctor.sh`, or this check will
always FAIL even though the account's own credentials are fine. See the "Multi-account
setups" section of `03-auth-and-rapt.md`.

<a id="missing-scopes"></a>
## ADC missing one or more scopes

The ADC file exists but doesn't carry all three required scopes
(`analytics.readonly`, `webmasters.readonly`, `cloud-platform`). This usually means it was
generated by a plain `gcloud auth application-default login` without the `--scopes` flag
this project's `reconnect.sh` supplies — for example if you ran gcloud's own login command
directly instead of `reconnect.sh`.

Regenerate it with the right scopes:

```
./scripts/reconnect.sh
```

Note that the granted scopes aren't stored inside the ADC JSON file itself — the file only
holds a refresh token and client details. To check what scopes a token actually carries,
you have to ask Google's tokeninfo endpoint, which is what `doctor.sh`'s `adc-scopes`
check does under the hood (exchange the refresh token for an access token, then query
`https://oauth2.googleapis.com/tokeninfo?access_token=...`).

Same multi-account note as above: pass `--account <email>` to `doctor.sh` if that
account's ADC lives under `.secrets/gcloud/<email>/`, so both the file it inspects and
the `gcloud` config it queries (`CLOUDSDK_CONFIG`) line up with that account.

<a id="apis-not-enabled"></a>
## Required GCP APIs not enabled

Three APIs must be enabled on the project in `GCP_PROJECT_ID`: `analyticsadmin.googleapis.com`,
`analyticsdata.googleapis.com`, `searchconsole.googleapis.com`. Check which are currently
enabled:

```
gcloud services list --enabled --project=YOUR_PROJECT_ID
```

Enable whichever are missing:

```
gcloud services enable analyticsadmin.googleapis.com analyticsdata.googleapis.com searchconsole.googleapis.com --project=YOUR_PROJECT_ID
```

<a id="native-module"></a>
## A native module fails to load

`search-console-mcp` depends on one native (compiled) Node module today: `@napi-rs/keyring`,
used to talk to your OS credential store. Native modules ship prebuilt binaries for
specific Node versions/platforms, and can fail to load — usually surfacing as a
`Cannot find module` error at server startup — when your Node version has no matching
prebuild.

Remedies, in order:

1. **Use an LTS release of Node**, not a very new or odd-numbered release — prebuilds
   typically lag the newest Node versions by weeks or months.
2. **Clear the npx cache** and let it re-fetch cleanly:

   ```
   npx clear-npx-cache
   ```

   or, if that command isn't available, remove npx's cache directory manually and retry.
3. **As a last resort, build from source locally:**

   ```
   git clone https://github.com/your-fork-or-upstream/search-console-mcp && cd search-console-mcp && npm install && npm run build
   ```

   Then point `.env` at the local build instead of `npx`:

   ```
   GSC_MCP_MODE=local
   GSC_MCP_PATH=/absolute/path/to/search-console-mcp/dist/index.js
   ```

   `setup.sh --print-mcp-config` and `doctor.sh` both honor `GSC_MCP_MODE=local` and will
   launch/check the local build instead of `npx -y search-console-mcp@2.0.1`.

### Historical note: `re2`

Up through v1.14.x, `search-console-mcp` depended on `re2`, a native regex module with no
prebuilds for Node 25 — installing or starting the server on Node 25 would crash outright.
It was removed in v2 (see upstream PR #81, fixing issue #80). If you're on v2.0.1 as this
project specifies, `re2` is not a factor; `@napi-rs/keyring` is the only native-module risk
left, and even that only affects the server's own internal credential-store access, not
the ADC-based flow this blueprint uses by default.
